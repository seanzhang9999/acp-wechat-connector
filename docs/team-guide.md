# 阿维团队体验指南 · v0.13.2

阿维是 AWiki WorkHub / AWiki Me 客户端的 AI 化身。本项目让你在微信管理和继续本机 Codex 会话：阿维理解管理请求，选中的业务会话负责实际工作，两者通过独立进程运行。无需 VS Code，也无需另配模型 API Key；仍使用配置的 ACP Agent 账号与额度。

## 1. 准备自己的环境

当前桌面启动、退出和恢复功能适用于 macOS。准备 Node.js 20+、可正常使用的 Codex 桌面、已经认证的 Codex ACP 提供方，以及能够完成 iLink Bot 配对的微信账号。每位测试者使用自己的配置和账号，不复制同事的 token、实例数据或生产启动脚本。

```sh
git clone https://github.com/seanzhang9999/acp-wechat-connector.git
cd acp-wechat-connector
npm ci
npm run build
cp config.example.json config.local.json
```

修改 `config.local.json`：`agent.cwd` 指向实际工作目录；`agent.env.CODEX_PATH` 与 `codexServer.command` 指向同一个桌面 App 内的 Codex 二进制。示例路径是 `/Applications/ChatGPT.app/Contents/Resources/codex`，请按本机实际安装位置调整。保留 `awei.enabled: true`。默认适配器通过 npx 获取；正式使用可固定已验证的适配器版本或绝对安装路径。

在独立终端首次前台启动并按提示扫码：

```sh
node dist/bin/wechat-acp.js --config config.local.json --instance personal-codex
```

完成配对后 Ctrl+C 正常停止，再后台启动，始终使用相同 instance：

```sh
node dist/bin/wechat-acp.js --config config.local.json --instance personal-codex --daemon
node dist/bin/wechat-acp.js status --config config.local.json --instance personal-codex
```

不要同时启动两个进程轮询同一微信账号。不要使用 `npx wechat-acp@latest` 更新本项目，它指向上游包。

## 2. 已安装用户更新（包括 Codex 桌面升级之后）

先等微信任务、审批、排队及附件发送结束，保存本地修改并备份自己的配置。以下流程适用于上述标准 daemon 安装；自定义启动器用户使用自己的服务管理方式，不额外启动第二个 daemon。

```sh
cp config.local.json "config.local.backup-$(date +%Y%m%d-%H%M%S).json"
git status --short
git pull --ff-only
npm ci
npm run build
npm test
node dist/bin/wechat-acp.js stop --config config.local.json --instance personal-codex
node dist/bin/wechat-acp.js status --config config.local.json --instance personal-codex
```

确认旧进程已退出，再执行上面的后台启动命令。`stop` 发送正常终止信号，停止返回不等于所有子进程已经退出；如果状态仍显示运行，应等待并核对，不能直接启动重复服务。存在本地改动或拉取失败时先处理差异，不执行 reset 或清理实例目录。

Codex 更新可能改变内置可执行文件路径、认证或协议。重新核对两处路径，先测试阿维帮助、列表与只读正文检索，再做下面的交接验收。构建测试通过不等于新 Codex 版本与手机链路已验收。

## 3. 微信侧五分钟上手

按顺序发送，每条等回复后再发：

1. `阿维，你能做什么`：看到管理帮助。
2. `阿维，列出最近会话`：返回候选；`阿维，下一页会话` 继续查看。
3. `阿伟，找一下旅行相关会话`：验证同音唤醒。按标题找与按正文找的意图要说清楚。
4. `A维，搜索对话正文里关于埃及酒店的讨论，读一下相关内容并告诉我结论和依据`：按正文搜索、定位、连续查阅后回答。它会给本次读取的来源；证据不够时应说明缺口。使用自己已有的主题替换例子。
5. `阿维，切到第二个`：仅在刚展示了有效候选后使用；随后 `阿维，现在是哪个会话` 核实目标。
6. `阿维，看看最近五轮对话`，再发 `阿维，再往前看`：查看历史。阅读和搜索本身不会切换当前目标或启动业务任务。
7. 普通文字如 `请根据刚才的方案列出下一步` 进入当前业务会话。业务会话被桌面持有时，先完成下一节的交接。

管理与业务分流依赖消息开头。`阿维`、`阿伟`、`阿唯`、`阿威`、`啊维`、`A维` 等可唤醒，称呼后可不加标点。正文中提到名字不触发。要把含称呼的文字交给业务会话，用 `转给当前会话：阿伟，这是一段待修改的文字`。

语音依赖微信提供转写；没有转写时按提示发文字。“潘伟”不属于唤醒词，重发 `A维，…` 即可。确认退出可说 `阿伟确认退出。`，但必须先有阿维发出的退出确认请求；不能用确认短句直接启动新的退出动作。

## 4. 从桌面 Remote 交给微信，再交回桌面

提前完成桌面的 Remote 配对并验证可连接，确保电脑在线且保持唤醒。首次测试应在电脑旁，或准备已经验证能启动桌面的独立备用通道。此前的十分钟兜底是一次本机独立测试监视器，不是本版本自动安装的功能。

| 步骤 | 微信操作 | 预期与验收 |
| --- | --- | --- |
| 基线 | `阿维，现在是哪个会话` | 阿维正常；手机 Remote 当前可连接 |
| 请求退出 | `阿维，关闭电脑上的 Codex` | 收到影响说明与确认要求 |
| 确认 | `阿伟确认退出。` | 收到正常退出成功；手机尝试新连/刷新 Remote 应无法继续连接该桌面 |
| 检查阿维 | `A维，列出最近会话` | 桌面关闭期间仍可回复 |
| 微信工作 | 选择测试会话并发普通消息 | 业务会话能运行并回复；不要使用正在处理重要任务的会话 |
| 交还 | `阿维，不聊了，恢复桌面`，再 `阿维，确认恢复` | 先释放业务连接，再启动桌面；阿维管理服务保持运行 |
| 验收恢复 | 从手机重新连接 Remote，在原业务会话继续 | Remote 实际连通，历史保留，可写；再问阿维帮助也应正常 |

精确命令用于排障：`/acp codex quit` 直接请求退出，不走自然语言二次确认；`/acp codex start`（别名 `open`）仅启动桌面；`/acp codex restore` 释放业务连接后启动桌面。`/acp release-all` 释放包括阿维在内的桥接连接，下一次管理请求按需重新连接；`/acp off` 仅切回原 ACP 聊天，不释放占用。

`start` 不释放微信持有的会话。Remote 使用桌面自己的服务，不能直接附着到阿维的独立 ACP 服务。共享本地历史不代表可同时持有同一会话的写入权。正常交还用 `restore`，不要为普通交接强制杀进程。

启动成功回复仅证明桌面及其 App Server 进程就绪，手机实际连接仍须手动验收。主机关机、休眠、断网或桥接未运行时，微信不能唤醒它。关闭桌面期间本地自动化不应视为可用；云端任务另按自身运行环境判断。本轮没有验证错过的定时任务是否补跑。

## 5. 附件与网页版体验

在选中的业务会话发送一张非敏感测试图片和一个小文本文件，要求 Agent 描述图片并引用文件内容，验证入站。再要求生成一个小文件，保存到当前工作目录并在最终答复使用 `[文件名](<绝对路径>)`，确认微信收到且能打开，验证出站。单个出站文件最多 25 MiB，每轮最多 10 个。路径可见不保证 Agent 沙盒有读取权限，失败应报告而不是静默丢失。

发送 `阿维，打开网页版演示`，点击返回的 GitHub Pages 链接并在微信浏览器查看。当前页面只有公开合成示例；不包含私人会话，也没有动态上传、飞书检索或真正的验证码保护。不要把公开 Pages 当私密资料交付入口。

## 6. 错误和反馈

- `SESSION_BUSY`：目标被另一个服务持有；管理请求先检查唤醒词，业务接管则正常退出桌面或释放原持有方。不要删除历史或复制会话来绕过。
- 没有对应待确认操作：重新提出退出/释放/恢复请求，在两分钟内确认相同动作。超时、动作不符和跨用户确认不会执行。
- 请求状态未知或发送失败：先用 `/acp result` 或查看原会话确认，避免盲目重发造成重复执行。
- 没有语音转写：改发文字，不把音频识别失败当作模型没有理解。
- 仍出现旧的 `Agent session error: Internal error`：记录时间、版本、截图，检查是否仍有旧桥接进程；单凭旧提示不能确定原因。

反馈请附：桥接版本、Codex 版本、macOS 版本、操作步骤、输入转写、预期/实际结果、错误编号、是否在微信或 Remote。日志只截相关时段并移除 token、账户和私人内容。

## 8. 形象反馈验收

发送“阿维，你能做什么”，应先收到帮助文字，再收到绿芽机器人欢迎图。请求一次较长的正文检索，超过 10 秒仍在处理时应收到工作图；不足 10 秒不发。每位用户每种图半小时最多一次，重启后计时重新开始。图片是进度陪伴，不证明检索成功；结论以最终文字及来源为准。图片使用提供的原图，保留 AI 标记。再打开网页版演示，检查页首欢迎图和下方守护者图在手机中完整显示。
