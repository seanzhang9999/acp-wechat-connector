# 阿维 · WorkHub 助手 v0.12

状态：v0.12.0 已实现。源码保留 ACP WeChat Connector 名称，微信侧助手叫“阿维”。

## 消息入口

纯文字以 `阿维，`、`阿维：` 或名字后空格开头，进入管理请求；单独发送“阿维”显示帮助。带转写的单条语音识别开头的“阿维”，容忍转写没有标点。原有 `/acp` 命令不经过模型。

其他消息直接进入已选择的业务会话；没有选择目标时仍使用原 ACP 聊天。`转给当前会话：...` 明确绕过管理/命令解析，可用于发送保留前缀。多附件消息保留既有路由，v1 不在附件内容或引用内识别唤醒词。

无转写语音会明确提示且不转发。当前语音支持指复用可选 `voice_item.text`，没有集成独立语音识别，也不能声称把 .silk 路径交给目标就能听懂。真实微信通道是否稳定提供转写仍需验收。

## ACP 语言服务

复用配置的 `agent.command/args/env` 和既有认证。阿维启动独立 ACP 进程与管理 session，工作目录是桥接私有存储下的 `awei-workspace`，不加载业务会话。进程按需创建；后续请求复用连接，释放全部或停止桥接时关闭。当前适配器可能把管理会话写入自己的会话历史；管理 ID 保存到私有存储中的 `internal-session-ids.json`，跨重启从桥接候选中过滤；同一管理工作目录中的旧会话会自动加入隐藏记录，其他客户端的原生历史展示不受本项目控制。

客户端不提供文件读写和终端能力、不挂载桥接 MCP，拒绝权限请求。要求适配器支持 `read-only` 模式，否则报错并保留精确命令可用。收到工具调用事件后取消推理并拒绝本次管理结果。

这里的 `read-only` 是适配器的模式 ID，不等于经过验证的操作系统级纯只读沙盒。适配器自带的本机工具能力取决于其实现；通知后取消也不保证撤销已开始的内部工具动作。因此 v1 的确定性保证是：桥接不会把模型输出作为任意命令执行，只接受允许的结构化管理动作；更强的提供方侧工具禁用仍待完善。

## 理解与执行

阿维每次收到用户原文、当前选择、有效候选及最近读取页。候选有效期 10 分钟，并绑定用户。每次最多 10 个检索/查阅动作，最后一次规划只允许回答或说明缺口；超过四分钟后不再启动新检索（正在进行的模型调用受单次超时限制）。搜索后可展示、查阅或选择；跨请求的编号解释以桥接当前候选为准。首次无候选时先搜索，不凭模型记忆生成 ID。

模型输出经严格 JSON schema 校验，允许 content_search/locate/read/answer/web_demo，以及原有 search/show/select/history/current/summarize/release/quit/off/clarify。未知字段、任意 shell 请求、虚构 ID、过期候选会失败，不回落业务会话。已切换/已释放等成功结果由实际执行函数返回。

最近会话检索每次最多 50 条。历史使用 `thread/turns/list`，按轮次分页，每页 1–20 轮；只保留用户及最终助手文本，排除工具、思考和 commentary。文本超过 16,000 字符会明确标记截断。历史读取不恢复写入会话；摘要只针对已读取部分。

## 会话交接与确认

自然语言 release/quit 形成两分钟有效的待确认操作。仅对应本人回复“阿维，确认释放/确认退出”才执行；“阿维，取消”取消。其他阿维请求会清除旧确认，重复确认不重复执行。精确 `/acp release-all` 和 `/acp codex quit` 维持原行为。

确认时先完成并关闭阿维自身 ACP 推理，再由独立桥接执行动作，避免管理进程阻塞自己的释放检查。业务任务、审批、消息缓冲和附件发送仍受原释放检查保护。

同一人的微信消息按到达顺序处理。切换请求完成前，后续语音/文字不会越过它。业务发送时固定目标，后来的选择不会改变已发送请求的回复归属。

- 真实 ACP 模型测试通过：正文查找、读取合成资料并给出带来源的答案，正确区分测试资料与真实安排。另通过本机真实正文搜索、命中定位及历史读取接口验证，查询后 loaded 列表为空。
- 尚未声称手机端唤醒、语音转写和新版本自然语言交接已完成实机验收。

会话列表按真实 ID 去重，包括连续翻页间的重复；重新搜索会重置去重记录。同名但 ID 不同的会话保留。阿维与 `/acp list` 共用此规则。隐藏与去重仅影响桥接列表，不删除或归档原始历史。历史测试会话可由维护者核对真实 ID 后加入本机隐藏记录，不按标题关键词批量隐藏。

## 正文检索与回答

`content_search` 使用 `thread/search` 搜索未归档会话，每页最多 12 条并返回命中片段；`locate` 使用 `thread/searchOccurrences` 获取命中位置；`read` 使用 `thread/turns/list` 读取位置对应轮次和更早对话，或从最近页向前翻页。查询不调用 resume/start，不改变默认目标。

模型通过结构化动作请求桥接执行受控的查询工具；ACP 原生工具继续禁用。每轮观察结果返回模型，支持换关键词、阅读多个会话后回答。每页最多 6 轮/12,000 字符，截断状态明确；来源 E 编号仅在本次实际读取后生成，回答引用经过校验，桥接追加真实会话名、ID 与轮次。来源校验保证读取出处，不代表模型结论自动正确。

当前只检索可见用户及最终助手正文；未归档范围、关键词匹配与结果分页均有边界。飞书、附件全文、语义向量索引、研究会话委派未接入。仅搜索列表时保留候选编号；读取资料可使用本次观察中的真实 ID，切换仍只接受有效候选。

## 网页演示与后续访问确认

“阿维，打开网页版演示”返回公开 GitHub Pages 合成示例链接，不发布实际对话。`web-demo/` 保存可审查的页面源码。浏览器验证与微信实机点击分别验收。

后续可采用“链接 + 微信单独发送数字验证码”：服务端校验后才提供私人内容，设置有效期和尝试次数限制。静态 Pages 页面中的前端验证码不能作为私人内容访问保护。本版不实现验证码或动态内容发布。
