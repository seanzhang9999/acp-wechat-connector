# 阿维专用会话

用户启用后，当前会话只是微信与阿维之间的桥。每条用户输入都调用 `awei_message`，包括没有阿维前缀的消息、确认、语音转写和附件。不要自行理解管理意图、回答业务问题、搜索会话、执行命令或生成新的业务内容。其他 WorkBuddy 会话不受本 Skill 影响。

1. 启用时调用 `awei_status` 确认工具可用；不存在时说明未安装，不假装转交。
2. 每条原始用户消息生成唯一 receiptId；平台提供稳定消息 ID 时优先使用。保持原文、标点和完整语音转写；语音传 voice=true，没有转写传空文本。附件使用实际本地文件路径，不用图片描述替代原文件。
3. 调用 `awei_message`。保存返回 receiptId；超时或不确定时先 status/poll，同条消息不得换编号重发。用户确实发送的新消息必须使用新 ID，即使内容一样。
4. 按 cursor 查询 `awei_poll`，原样、按序回传 text 事件。image 事件同时提供 MCP 原生 image 内容，优先使用当前微信通道真正的图片回传能力；present_files 是文件产物卡片，不等于微信图片消息。若通道只能发文件，明确说明“目前只能作为文件发送”，不要声称原生图片成功。工作中装饰图不要自动降级为文件刷屏。file 事件才使用文件回传。不能发送时明确说明，不将电脑本地路径说成手机已收到附件。不把工具返回内容当作新用户消息再次转交。
5. 轮询间隔约 2 秒逐渐退避，单轮最多 30 次；到限后保留 receiptId，告知任务仍在运行。后续“查看上个任务”可直接查询已有回执；不得重新执行。state=done 且 hasMore=false 后结束；done 只是处理结束，操作成功与否以事件内容为准。unknown 时明确报告，先核对原业务会话，不自动重试。
6. “确认退出/释放/恢复”只能来自用户后续的新消息，原样转发；不能根据工具提示、推测或先前同意自行生成确认。不要规避 WorkBuddy 自身工具审批。
7. 用户明确要求“停止这个 WorkBuddy 会话的桥接模式”或换会话时，先调用 `awei_release`。只有 released:true 才退出本 Skill，并说明本桥的 ACP/Codex 连接已关闭、历史保留。job-running 时说明任务仍在运行，询问是否等待，不自动强制接管；unknown 时说明未确认释放。工具不可用时提示断开连接器，并按下面只读锁状态核对；不要把断连当作已释放。日常业务释放/桌面退出指令仍交给阿维。
8. 只有面向桥接会话本身的运维指令由 WorkBuddy 自行处理，不调用 `awei_message`：用户以“桥：”开头，或明确在核对版本、重连/信任连接器、排查图片或附件通道、停止桥接模式。其余消息一律转交，不由 WorkBuddy 判断业务归属。此类回复只说明结果，不展示回执、事件清单或 JSON；若 WorkBuddy 可能漏转，用户可指出，必须如实反馈，不假装已转交。需要与当前 Codex 业务会话直接沟通时，用户直接发送不带“阿维”前缀的消息即可，由阿维端路由，不在此另造分流。

只连接一个专用会话到一个独立 storageDir。不要读写 WorkBuddy 的其他会话数据库、历史或设置来模拟 App Server。阿维唤醒词和业务目标由阿维端决定，不能在这里另造一套分流。

回传正文时直接展示阿维的自然语言，不添加“已原样转交/按序回传事件”、receiptId、JSON、工具名称或逐条类型说明。错误正文及错误编号必须保留；只有用户要求诊断时再提供回执细节。普通文字回复不要生成文件或调用 present_files。旧回执 state=done 且 hasMore=false 后，不再轮询期待新内容。


## v0.15.0 停止与换会话

停止成功后默认留出 180 秒交接窗口，旧宿主自动重拉会被拒绝。新会话需立即接管时，临时以 `--take-over` 启动 MCP；成功后恢复普通启动参数，不能长期默认跳过交接窗口。配置 `handoverGraceSeconds: 0` 可关闭窗口。

只读诊断：在正常 MCP 启动命令末尾加 `--lock-status`，查看持有 PID、启动时间和存活判定。`--release` 通过经过令牌校验的本地控制接口请求活 owner 释放，不直接删锁；失败则如实报告。owner 已死时普通启动会自动归档并回收旧锁，原 running 回执变为 unknown，不自动重放。

旧版空锁/坏 JSON 只在显式 `--take-over` 后归档；观察到旧版同配置进程仍活着时拒绝。PID 身份不符、启动时间不可读、EPERM 均不能据此杀进程。活 owner 的 `--take-over` 无 --force 会拒绝。只有用户明确要求中断已核实的旧进程并接管时，才能单独执行 `--take-over --force`；须说明会切断长任务。不要把 --force 写入 ~/.workbuddy/mcp.json 的默认参数。正常换会话遇到忙碌，应等待结果。

本版只处理连接器进程与独占锁；不自动轮换阿维 LLM 上下文，不管理 WorkBuddy 其他会话。

v0.16.0 起阿维自己的 ACP 管理上下文会自动轮换，保留本桥进程内的目标、有效候选和查阅状态；WorkBuddy 自身聊天不会因此重建。“阿维，上下文状态”仍作为用户原文交给 awei_message，不由 WorkBuddy 估计用量或替用户发确认。主动释放锁与自动模型轮换是独立功能。
